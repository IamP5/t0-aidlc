## 0. Two facts that shape every fork decision

1. **Invocation rule (mattpocock).** A skill with `disable-model-invocation: true` is user-invoked: no other skill can call it through the Skill tool (`MP/.agents/invocation.md`). Only these 11 mattpocock skills are model-invoked and therefore *wrappable* from our `/bet-*` skills: `grilling`, `domain-modeling`, `codebase-design`, `code-review`, `diagnosing-bugs`, `research`, `prototype`, `pr`, `tdd`, `wizard`, `writing-for-agents`. Everything else (`to-spec`, `to-tickets`, `implement`, `implement-spec`, `grill-with-docs`, `retro`, `handoff`, `triage`, `wayfinder`, `setup-matt-pocock-skills`, `ask-matt`, `to-questionnaire`, `teach`, `wait-what`, `grill-me`) can only be **forked**, never composed.
2. **pstack is almost entirely user-invoked.** Every pstack skill except `setup-pstack` sets `disable-model-invocation: true`, including all `principle-*`. Its own Claude Code adapter (`PS/docs/harness/claude-code.md`, Tools table) says "The `Skill` tool refuses most pstack skills" and tells the agent to `Read` the SKILL.md instead. So pstack content we want must be **forked**, not wrapped.

## 1. How mattpocock locates the issue tracker

- `/setup-matt-pocock-skills` (`MP/skills/engineering/setup-matt-pocock-skills/SKILL.md`) writes an `## Agent skills` block into `CLAUDE.md` (else `AGENTS.md`) with three sub-blocks, each pointing to a file under **`docs/agents/`**: `issue-tracker.md`, `triage-labels.md` (only if `triage` installed), `domain.md` (lines 84-114).
- Skills never hard-code the path. Hard-dependency skills (`to-spec`:9, `to-tickets`:11, `implement-spec`:9, `code-review`:13, `wayfinder`) say "The issue tracker ... should have been provided to you. If not, tell the user to run `/setup-matt-pocock-skills`" (ADR `MP/.agents/adr/0001-...`). CHANGELOG 1.1.0 confirms wayfinder was fixed to resolve via the CLAUDE.md pointer too.
- Seed templates: `issue-tracker-github.md` (`gh`), `issue-tracker-gitlab.md` (`glab`), `issue-tracker-local.md` (`.scratch/<feature>/spec.md` + `.scratch/<feature>/issues/NN-slug.md`, "never a single combined tickets file"). A tracker doc must answer: **Conventions** (create, read, list, sub-issue/parent, comment, labels, close), **"When a skill says publish to the issue tracker"**, **"When a skill says fetch the relevant ticket"**, and **"Wayfinding operations"** (map, child, blocking, frontier, claim, resolve).
- **Jira is explicitly out of scope** (`MP/.out-of-scope/mainstream-issue-trackers-only.md`; rejected requests #258 "Jira via Rovo MCP" and #1137 "Jira via acli"). The sanctioned route is the **Other** option: the user describes the workflow, setup records it as prose in `docs/agents/issue-tracker.md`. That file is ours to write.
- Domain docs: `GLOSSARY.md` (+ `GLOSSARY-MAP.md` for multi-context) and `docs/adr/`. Rename from `CONTEXT.md` confirmed in CHANGELOG 1.3.0 (#1120). `to-prd`→`to-spec` and `to-issues`+`to-plan`→`to-tickets` confirmed in CHANGELOG 1.1.0 (#464, #734). Default triage roles: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`.

Upstream: multi-model adversarial review; the lead buckets findings Act on / Consider / Noted / Dismissed and only weights "a concrete execution path" as a signal (`interrogate/references/lead-judgment.md`). Proving by running code is **blast-radius** (and `principle-prove-it-works`). In Claude Code both reviewers run on the session model (adapter Models table), so interrogate loses its diversity. Swap the Verify row to blast-radius.
2. **interrogate is not the only skill that loses model diversity.** show-me-your-work's "Attention" also requires "a different model family" (lines 67-76). Same-family review must be labelled.
3. **show-me-your-work is not committed by default.** Upstream: "By default the log is a working artifact, not committed ... leave it out of git" (lines 46-50). "Commitado por PR" is our policy and needs the fork. `.audit/<slug>.tsv` is upstream's own path for concurrent efforts, so `.audit/<KEY>.tsv` matches.
4. **Privacy list is incomplete.** Besides automate-me, recall, reflect: `MP retro` searches "session logs on this machine" (line 13); show-me-your-work's audit reads the run transcript (lines 57-65); `PS why` auto-discovers and queries every connected MCP (Slack, Datadog, Notion, Sentry...). recall pulls `why` in.
5. **git-guardrails cannot be used "in the style of" as-is.** It lives in `misc/` (frozen, not shipped in the plugin) and blocks **every** `git push`, which breaks the draft-PR flow. It also collides with pstack playbooks that use `git reset --hard origin/<branch>` (`opening-a-pr.md:5`) and `--force-with-lease` (`autopilot-full.md:12`, `shipping.md:8`). Fork the pattern list (§5) and do not adopt poteto-mode playbooks.
6. **"/bet-shape: grill-with-docs + architect" can't be built by composition.** grill-with-docs and every pstack skill are user-invoked; the Skill tool won't call them. /bet-shape calls `grilling` + `domain-modeling` and forks architect's text. Also architect **skips the human checkpoint by default** (Phase C opt-in) and goes straight to implementation, against "humano atua no Shape".
7. **"/bet-spec: template traduzido, grava spec.md" is more than a translation.** to-spec publishes to the tracker and applies `ready-for-agent` (line 19). It also has no acceptance criteria, no "como verificar" and no tier; upstream puts AC in to-tickets. The DoR fields have to be added.
8. **tasks.md (single file) contradicts upstream's ticket convention.** to-tickets and the local tracker write "one file per ticket ... never a single combined tickets file". Either keep `tasks.md` as an index plus one file per slice, or state it in our tracker doc and fork the lines.
9. **implement/implement-spec autonomy.** implement-spec step 8 "mark it ready for review" (line 38) and implement "Commit your work to the current branch" (line 17, no PR) both need edits for the draft-PR rule. "implement-spec só em Tier 0/1" is fine.
10. **pstack tdd isn't a general TDD skill.** It's a narrow regression-test skill for bug fixes ("Use only when the user explicitly asks"). Listing it beside mattpocock tdd in Build misleads; drop it.
11. **"skills de verificação formal" doesn't exist in pstack 0.15.25.** There is no formal-verification skill. The nearest names are `create-verification-skill` and `maintain-verification-skill`, which the doc **adopts**. Reword or name what was meant (benchmark-checklist? principle-explain-the-number?).
12. **create-/maintain-verification-skill are Cursor-pathed.** They write `.cursor/skills/verify-<app>/`, and maintain opens a ready PR. Both need path and draft edits.
13. **reflect auto-files to a tracker.** "File each Backlog item ... without waiting" (line 51) is an external write without approval. It also relies on Cursor's `create-skill` (lines 56-58).
14. **handoff already redacts.** Upstream line 14 tells the agent to redact secrets and PII. So "com varredura de segredos" adds a *deterministic* scanner to a concern upstream already covers. Output goes to `$TMPDIR`, outside the repo.
