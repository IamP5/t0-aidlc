# v0.1: the cut we build now

**Goal.** One pod can run a bet end to end inside the KB:

```
idea → bet → shape/spec → G2 → plan/slices → G3 → slice-build (draft PR) → slice-verify
```

This has to work from Claude Code, with Copilot CLI and Kiro loading the same plugin. Specifically:

- every step lands in the KB through the records lane or a knowledge PR
- derived state is folded by `kb render`
- the checker is green
- the eval suite passes

**Budget.** One agent team, a few hours. That only works if the sketch interfaces are frozen first and the six streams build against them in parallel.

## Hour 0: freeze the contract (lead agent, ~30 min)

- Copy `sketch/t0/**` into `src/t0/`. The bodies stay `raise NotImplementedError`.
- Add `pyproject.toml`, the import-linter contract, and an empty pytest run.
- Commit. Every stream branches from this commit, and changing a signature after it needs a note in the PR. That is a Phase D deviation, and the note makes it visible instead of letting it slip in silently.
- Copy `tests/fixtures/kb-payments/` (hand-written: payments product, BET-042 with 3 slices across 3 repos, BET-051 bugfix, 3 ideas, steps, one G1 gate file). It is the shared fixture every stream tests against.

## v0.1 command surface (subset of `cli.COMMANDS`)

```
t0 kb check|find|get|propose|push|status|render
t0 new idea|bet (incl. --bugfix)|spec|plan|slice|adr|assessment|contract|harness
t0 log <kind> "<texto>"
t0 gate G0|G1|G2|G3 <ref> [--to]          (G4/G5 --ci: planner + records, CI wiring deferred)
t0 context [ref] [--format ...]
t0 ws init|sync          (minimal)  t0 bet start|use|detect   t0 slice start   t0 pr
t0 transcript redact     (dry-run only: prints report, persists nothing; Policy persist=false)
t0 jira sync [--apply]   (file tracker only; --apply allowed only with tracker: file in v0.1)
t0 gen [--check]   t0 setup --kb   t0 mcp   t0 hook <name>
```

## Exit criteria (all must hold)

1. `pytest` passes; `t0 gen --check` is clean; `claude plugin validate plugin --strict` passes.
2. `t0 kb check --level L2` reports 0 errors on `templates/okf-kb` and on the fixture (fixture warnings equal the golden).
3. Scripted e2e against a scratch copy of the template plus a bare remote (`tests/e2e/test_bet_flow.py`):
   1. `new idea`, then `push` (records PR on the file forge)
   2. `new bet --from IDEA`, then `propose`
   3. `gate G2` is refused because of markers; after the markers are fixed, `gate G2` and `propose` succeed
   4. simulated merge, then `kb render --commit`
   5. `spec.md` now has derived `state: approved`, `status: stable` and `verified`, and the bet `log.md` has the lines
   6. `jira sync --apply` (file tracker) emits `jira-linked` records, and the next render folds the `jira:` keys
   7. `gate G3` passes
4. Eval cases 1-15 pass at ≥2 of 3 runs in `claude plugin eval`.
5. Manual smoke: the plugin loads in Copilot CLI (`copilot plugin install ./plugin`) and kiro-cli (`t0 install`-equivalent copy documented in the README). In each, cases 5 (gate refused) and 9 (draft PR) are run by hand and the transcripts are attached to the release notes.
6. The `t0-kb` repo is created from the template; its CI runs `kb check` green on the first PR; and BET-001 exists in it.

## Risks to this cut

- **Stream C is the bottleneck: `propose` plus the plumbing push.** Mitigation: the bare-repo test harness comes first, and the forge file backend unblocks F's evals before GitHub REST is done.
- **Eval flakiness on trigger cases.** Trigger cases run `--runs 3`, and v0.1 accepts ≥2/3 pass.
- **Unverified GHE behaviours** (records-PR auto-merge with 0 approvals, App bypass for kb-render) cannot be tested in this session. v0.1 runs them against the file forge, and the bank-side verification list from workspace-pattern §8 becomes the first slices of BET-001.
