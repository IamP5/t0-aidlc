# v0.1: the cut we build now

The budget is one agent team and a few hours. The rule for the cut: everything that makes the KB conformant and writable through `t0` in the three tools, plus the skills a dev needs to run one bet from `bet-new` to a draft PR. Anything needing an unknown (Jira flavour, GHE auto-merge policy, cloud agent setup) ships as a port + fake, not an integration.

## Ships

**OKF template (`templates/okf-kb/`)**
- `profile.md` with the full registry: types Bet, Bugfix, Spec, Plan, Slice, Contract, ADR, Idea, Product, Workspace, Ritual, Ritual Record, Transcript, Cycle Record, Step, Changeset, Log, Template, Glossary Term, Person, Role Archetype, Accountability, Rotation, Principle, Practice, Policy, Playbook, Harness Item, Metric Snapshot, Eval Suite, Adoption Report, Assessment, PI Outcome, Research, Reference; gates G0-G8 as data; lanes; actors.
- Templates for the types `scaffold()` produces in v0.1 (bet × 4, bugfix, spec, plan, slice, idea, adr, ritual-record, transcript, step).
- The `exemplo` product with one bet, one cycle, one ritual record, one redacted transcript, one step, rendered `index.md`/`log.md`/`changeset.md`; 12 rituals as concepts; principles, practices, policies (`proposed`); glossary with 5 terms; CODEOWNERS; the two KB workflows (`kb-check`, `kb-render`).

**Checker**: L0 and L1 complete; L2 rules `relation-target-missing`, `stale-past`, `rotation-uncovered` (the rest deferred). Records-lane mode. `--format github|text|json`.

**Core CLI** (`t0`): `kb check|render|record|push|status|find|get|propose`, `log`, `bet new|start|use|detect`, `slice start|dor|get`, `gate G0–G8` (plan + apply through the knowledge lane; G4/G5 callable but their CI wiring is deferred), `ritual <slug> open|close` (generic; `pre` computations for mob-a; betting/demo without archetype/metrics rules), `context` (all formats), `transcript redact`, `adr new`, `idea new`, `gen [--check]`, `setup [--check]`, `install --user`, `hook <event>`, `mcp`, `jira sync --adapter fake [--dry-run]`, `pr open --draft` (via `gh`), `trace`, `doctor` (card freshness, instructionFiles, spool only).

**MCP read + records write**: `kb_context`, `kb_search` (rg with Python fallback), `kb_get`, `bet_get`, `changeset_get`, `kb_record` → spool. Instructions ≤ 1500 chars.

**Writes**: records lane end-to-end (spool → push → PR with auto-merge flag, batch mode switch present), knowledge lane `propose` (branch + draft PR via `gh`), derived lane `render` (`--write` for CI, check mode for PRs), idempotent.

**Skills (12 + 3 thin)**: `pack-setup`, `kb-check`, `bet-new`, `bet-use`, `bet-shape`, `bet-spec`, `bet-plan`, `bet-slice`, `gate`, `ritual`, `slice-build`, `slice-verify`; `kb-record`, `kb-search`, `handoff`. Forks carry `metadata.credits`; `THIRD_PARTY_NOTICES.md`.

**Hooks**: six events through `t0 hook` with the three-line shell wrappers; Claude `hooks/hooks.json` (Copilot CLI reads it); Kiro `.kiro/hooks/t0.json` and Copilot cloud `.github/hooks/t0.json` generated by `t0 gen`. Guard: dangerous git, derived-file edits, existing steps edits, absent repos.

**Adapters**: `t0 gen` for the three targets at plugin, workspace, repo and user scope; `--check` with drift report and the skill/CLI-call cross-check. Both manifests.

**Evals**: layer 1 full for the shipped modules; layer 2 first 10 cases; layer 3 negative fixtures for every implemented rule; layer 4 interface only. CI: pytest, import-linter, `claude plugin validate --strict`, `t0 gen --check`, `t0 kb check` on the template.

## Order of work (so the team can parallelise)

1. `okf.py` + `profile.py` + template `profile.md` + positive fixture (one person). Everything else imports these.
2. `checks.py` L0/L1 + negative fixtures (one person, after 1 lands the types; can start writing fixtures from the profile text).
3. `records/knowledge/render/scaffold/writer` + `forge` via `gh` (one person).
4. `redact.py`, `card.py`, `workspace.detect_bet` (one person; pure, no dependencies beyond `okf`).
5. `gate.py`, `ritual.py` (after 2 and 3).
6. `gen.py` + hooks + both manifests + `cli/` + `mcp/` (one person; shells are mechanical once 1-5 expose the API).
7. Skills (one person, in parallel from the start: they only need the CLI noun/verb names in `cli.py`'s docstring).
8. Evals layer 2 cases and mocks (last; needs 6 and 7).
