Two manifests, one directory: Claude reads `.claude-plugin/plugin.json`, Copilot CLI prefers root `plugin.json` (Agent Plugins) and also reads the Claude hooks file, Kiro reads root `plugin.json` + `skills/` + `mcp.json` and is expected to ignore `.claude-plugin/` and `hooks/` (to verify, workspace-pattern §8). `t0 gen --check` keeps the two manifests' `name`/`version`/`description` equal.

## KB template: `templates/okf-kb/` (→ `t0-kb`)

Only what the template needs to be a conformant, runnable bundle on day one. Everything a team adds follows the same patterns. All paths bundle-absolute.

```
okf-kb/
  index.md                          # frontmatter: okf_version: "0.2" only; body rendered by render()

  log.md                            # type: Log; team-level events only (rendered from /cycles/*/steps)
  CODEOWNERS                        # /methodology/ @lead ; /products/*/bets/BET-*/ @bet-owner-rotation ; /cycles/*/rituals/ @facilitators ; **/steps/** (no owner)
```

Notes:

- The example product `exemplo` plus one cycle makes the template exercise every type, every lane and every derived file; `tests/fixtures/kb-positive` is this directory, so the template cannot drift from the checker.
- `methodology/templates/*.md` are concepts (`type: Template`) so OKF consumers see valid frontmatter; `scaffold()` strips the Template frontmatter and instantiates the `for_type` keys.
- `profile.md` is the only large frontmatter in the bundle; its body is derived. Splitting into `/profile/types/*.md` is a loader change only (open question in rationale).
- No `CLAUDE.md` anywhere in the KB; a root `AGENTS.md` is not needed because the KB is reached through the workspace card and the MCP server.
